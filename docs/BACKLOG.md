# Noki — бэклог по итогам аудита

Дата аудита: 12 сентября 2026, коммит `af23efa` («Продакшн-деплой на noki.click»).
Полная версия отчёта с разбором по ролям: артефакт «Аудит Noki».

Как пользоваться: каждая задача имеет сквозной номер. Номер не меняется,
даже если задача переезжает между приоритетами. Называйте номер — делаем.

Приоритеты:

- **P0 — немедленно.** Риск необратимой потери данных или репутации. Делать до
  любой другой работы.
- **P1 — до приёма денег.** Без этого нельзя открыть платную подписку.
- **P2 — масштаб и удержание.** Нужно, чтобы выдержать десятки тысяч
  посетителей и чтобы команды оставались после trial.
- **P3 — Enterprise и желательное.** По запросу клиентов или когда закрыто
  всё выше.

Оценка трудоёмкости: **S** — до дня, **M** — 2–5 дней, **L** — 1–3 недели,
**XL** — больше. Для одного разработчика полной занятости.

Ссылки на файлы относительны корня репозитория.

### 19. Тарифная сетка и seat-модель
**S решение** · продукт, биллинг

Предлагаемая сетка (цены не заданы — зависят от рынка и провайдера, см. №45):

| Параметр | Free | Team | Enterprise |
|---|---|---|---|
| Для кого | индивидуал, пробный Space | команды 3–50 человек | компании с ИБ-требованиями |
| Цена | 0 | за место в месяц, годовая со скидкой | договор, инвойс, от N мест |
| Участников в Space | 3 | по числу мест | без лимита |
| Teams / Boards / Pages | 1 / 2 / 5 | без лимита | без лимита |
| Задач в Space | 300 | без лимита (мягкий 50 000) | без лимита |
| Хранилище | 200 МБ | 5 ГБ + 1 ГБ за место | по договору |
| Публичный API | только чтение, 100 req/мин | чтение и запись, 600 req/мин | отдельные лимиты, вебхуки |
| Гостевые роли и viewer | — | да | да |
| История и корзина | 7 дней | 90 дней | настраиваемо |
| Аудит-лог | — | 90 дней в UI | экспорт, SIEM |
| SSO / SCIM | — | — | SAML, OIDC, SCIM |
| Шифрование | общий ключ | общий ключ | выделенный ключ (BYOK), self-hosted |

Лимиты Free нарочно выше сегодняшних (2 Space, 3 Team, 3 Board, 3 Page):
бесплатный тариф должен дать почувствовать продукт. Ограничивать то, что
растёт с командой: людей, хранилище, API.

Seat-модель:
- Место = активный SpaceMember. Гости и viewer не считаются.
- Добавление сверх мест → 409 с предложением докупить; owner подтверждает,
  провайдер получает `update_seats` с пропорциональной доплатой.
- Удаление участника уменьшает места со следующего периода.

### 20. Жизненный цикл подписки и режим read-only
**M** · биллинг, backend

Состояния:
- `trialing` — 14 дней Team без карты после создания Space; по окончании
  автоматически Free.
- `active` — оплата прошла, лимиты плана.
- `past_due` — платёж не прошёл: 7 дней dunning-писем, функционал не режется.
- `read_only` — после grace: создание и редактирование запрещены, чтение и
  экспорт работают. Данные не удаляются без явного действия владельца.
- `canceled` — по окончании периода переход в Free; при превышении лимитов
  Free Space остаётся в `read_only` до сокращения.

Middleware/зависимость, которая проверяет статус Space на любой мутации.
После: №17, №8.

### 30. Решение по поиску при шифровании полей
**S решение + L реализация** · архитектура

Заголовки задач, страниц, комментарии и todo лежат как ciphertext
(AES-256-GCM с AAD таблица+id+поле). Любой поиск, фильтр по названию,

на Space. Решить до фазы «поиск» (№31).

Варианты:
- (а) Blind index HMAC-SHA256 по нормализованному заголовку для точного
  совпадения.
- (б) Отдельный поисковый индекс (Meilisearch или OpenSearch) с шифрованием
  на диске и строгим ACL по Space; туда пишутся расшифрованные заголовки и
  текст.
- (в) Пересмотреть границу: шифровать только описание задач и содержимое
  страниц, заголовки хранить открыто, полагаясь на шифрование диска и БД.

Где: `backend/app/services/content_encryption.py`,
`backend/app/models/issues.py`, `backend/app/models/page.py`.

### 33. Изображения в S3-совместимом хранилище

### 48. Нагрузочные тесты и целевая топология
**M** · SRE

Оценка: 30 000 визитов в день × 10–15 API-запросов = 300–450 тыс.
запросов в сутки, 3–5 rps в среднем, 40–60 rps в пике. Один воркер держит,

запись при 100 одновременных пользователях; найти, что ломается первым.

Целевая топология для 10–50 тыс. визитов в день:
- CDN перед всем, TLS там же, origin закрыт по IP.
- Выделенный VPS 4 vCPU / 8 ГБ: nginx, 2–3 uvicorn-воркера, Next,
  Celery worker × 2, beat.
- Managed PostgreSQL или отдельный VPS с PgBouncer и WAL-архивацией.
- Redis отдельный, с паролем, `maxmemory`, политика для кеша отдельно от
  очереди.
- S3-совместимое хранилище для изображений и бэкапов.
- Sentry + Prometheus + Grafana + внешний uptime.

Горизонтальное масштабирование позже: приложение stateless (сессии, лимиты,
lease уже в Redis), Celery beat остаётся один, worker'ы масштабируются,
единственная привязка к хосту — локальный диск (№33).

## P3 — Enterprise и желательное

### 59. Политика хранения и partitioning
**M** · БД

Ни у одной таблицы нет TTL: комментарии, события, инвойсы и аудит будут
расти бесконечно. Привязать retention к плану, partitioning по месяцам для
`audit_log` и `task_events`.

### 60. Дробные позиции задач
**S** · БД

Reorder переписывает `position` всех задач доски за один PUT: при 1000 задач
это 1000 UPDATE под блокировкой доски. Fractional indexing или `numeric`
позволят менять одну строку.

Где: `backend/app/api/routes/issues.py` (`reorder_tasks`).

### 61. Второй фактор: TOTP, WebAuthn, принудительный 2FA
**L** · безопасность

Реализовано: добровольный TOTP для аккаунтов, резервные коды и обязательный
TOTP при административном step-up. WebAuthn и принудительная политика для
организации остаются задачами Enterprise и требуют отдельного дизайна
восстановления доступа.

### 62. Управление сессиями и оповещения о входе
**S** · безопасность · выполнено

Список активных сессий, user-agent, IP и отзыв одной сессии добавлены. Письмо
о новом входе отправляется при парольном и Google-входе; оно приходит при
каждом новом входе, чтобы вход с похожим user-agent не остался незамеченным.

### 63. Единый источник заголовков безопасности
**S** · безопасность

HSTS ставят nginx (`max-age=63072000; includeSubDomains`), Next
(`max-age=31536000`) и backend (`max-age=31536000; includeSubDomains`);
Referrer-Policy у nginx `strict-origin-when-cross-origin`, у backend
`no-referrer`. Оставить один источник — nginx.

Где: `nginx.conf`, `frontend/next.config.ts`, `backend/app/core/middleware.py`.

### 64. Фискализация и НДС
**S решение** · право

Для РФ — чеки по 54-ФЗ через платёжного провайдера; для ЕС — VAT по стране
покупателя или Merchant of Record. Определяет выбор провайдера (№21).
После: №45.

### 65. Security Whitepaper и DPA
**S** · право, продажи

Enterprise попросит DPA, SOC 2 или хотя бы описание мер. Две страницы:
шифрование, сессии, бэкапы, инцидент-менеджмент, субпроцессоры.

### 66. Envelope encryption и ротация ключей (BYOK)
**L** · безопасность, архитектура

CheckConstraint `encryption_key_version = 1` стоит на пяти таблицах, ключ
один на установку — ротация невозможна по конструкции. Для Enterprise: KEK
в KMS или Vault, DEK на Space, обёрнутый KEK, версионирование, фоновая
перешифровка, BYOK.

Где: `backend/app/models/*.py` (`encryption_key_version_valid`),
`backend/app/core/encryption.py`.

### 67. SSO (SAML/OIDC), SCIM, self-hosted
**XL** · Enterprise

SSO, SCIM-провижининг, Docker-образы и инсталляция self-hosted (№57),
аудит-лог с экспортом в SIEM (№25), SLA.

### 68. Исходящие вебхуки и расширение публичного API
**M** · backend

Публичный API не покрывает Pages, Todos; нет исходящих вебхуков на события
задач (для Slack, GitHub, Zapier). Расширить scope токенов: `pages:read`,
`webhooks:manage`.

Где: `backend/app/api/routes/public_api.py`, `backend/app/models/api_token.py`.

### 69. Ключ доски 2–5 символов
**S** · продукт

Ограничение `^[A-Z]{3}$` на уровне БД и схемы; в большинстве трекеров
допустимы 2–5 символов. Миграция с изменением CHECK, схема, онбординг.

Где: `backend/app/models/issues.py` (`key_format`),
`backend/app/schemas/issues.py`, `frontend/src/app/app/onboarding/page.tsx`.

### 70. Виральные петли
**M** · рост

Приглашение по ссылке (№12), публичные страницы только для чтения с
брендингом, шаблоны Space, «создано в Noki» в экспорте.

### 71. Единый API-клиент для токенов
**S** · frontend

`getApiTokens`, `createApiToken`, `revokeApiToken` обходят `apiFetch` и не
получают автоматический refresh и таймауты.

Где: `frontend/src/lib/api.ts`.

### 72. Гостевые роли и viewer
**M** · продукт

Роли только owner/admin/member. Для плана Team нужны guest (доступ к
одной команде) и viewer (только чтение), не считающиеся местами (№19).

Где: `backend/app/services/memberships.py`.
