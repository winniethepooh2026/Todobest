# Transactional email

Noki sends transactional mail through Resend. API requests use the existing
`httpx` dependency, a 15-second timeout and Resend `Idempotency-Key` headers.
Celery retries transient failures with exponential backoff in the dedicated
`mail` queue, consumed by the `noki-mail-worker` PM2 process.

## Production setup

1. Add `noki.click` (preferably a dedicated subdomain such as
   `mail.noki.click`) in the Resend Domains dashboard.
2. Copy the exact SPF/MX and DKIM records generated by Resend into the DNS
   provider. Values are account/domain-specific and must not be guessed.
3. Wait until the domain status is `verified`.
4. Publish `_dmarc.noki.click` as TXT, initially:
   `v=DMARC1; p=none; rua=mailto:dmarc@noki.click;`. Confirm `spf=pass`,
   `dkim=pass` and `dmarc=pass` on real messages before moving gradually to
   `p=quarantine` and then `p=reject`.
5. Set `RESEND_API_KEY`, `MAIL_FROM`, `MAIL_REPLY_TO` and the TTL variables in
   the production `.env`. `MAIL_FROM` must use `noki.click` or a verified
   subdomain, for example `Noki <no-reply@noki.click>`. Эти значения остаются
   серверными: PM2 не передаёт их frontend-процессу.
6. Run the migration and reload all PM2 processes. Verify that
   `noki-mail-worker` consumes only the `mail` queue.

## Templates and triggers

Templates are code-owned in `app/services/mail.py`: email verification,
password reset, invitation, new-login alert and account notices.

The Resend idempotency window is 24 hours. Every request key is derived from a
database event identifier so Celery retries do not duplicate a message.

## Abuse controls

- Registration is limited per source IP and to three verification messages per
  recipient per hour.
- Password reset is limited per source IP and to three reset messages per
  recipient per hour. Recipient throttling keeps the same generic response, so
  it cannot be used to discover whether an account exists.
- Invitations are limited per authenticated actor and per recipient. An active
  invitation for the same Space/Team and address cannot be duplicated.
- New-login notifications are capped per recipient without blocking a valid
  login. Space exports are capped per authenticated user.
- The dedicated Celery worker also applies a global `120/m` delivery ceiling,
  while Resend idempotency keys make retries safe.

Defaults are configured through `MAIL_RECIPIENT_RATE_LIMIT_ATTEMPTS`,
`MAIL_RATE_LIMIT_WINDOW_SECONDS`, `INVITATION_MAIL_ACTOR_RATE_LIMIT_ATTEMPTS`
and `EXPORT_RATE_LIMIT_ATTEMPTS`.

## Secret rotation

Create the replacement key in Resend, update the production secret, reload the
API and workers, verify a test email, then revoke the old key. Keys shared in
chat or logs must be rotated after setup.
